# 为什么不是又一个框架

## 一句话

**NexAgent 是 Mastra 的适配层，不是它的竞品。**

## 与 Mastra 的确切关系

| 问题 | 答案 |
| --- | --- |
| 是 fork 吗？ | **不是。** Mastra 在 `package.json` 里，不在源码里。 |
| 会复制它的代码吗？ | **不会。** 若你在本仓库看到 Mastra 源码，那是 bug，请提 Issue。 |
| 上游升级怎么办？ | 改版本号即可。我们只依赖它的公开 API。 |
| 许可冲突吗？ | 不冲突。本项目 MIT；Mastra 核心 Apache-2.0。 |
| 它有的功能我们还做吗？ | **不做。** Agent / Workflow / Memory / RAG / Evals 全部交给它。 |

## 我们做什么（也就是「改什么」）

### A 档 · 合规与品牌底线（必须）

| 项 | 做法 | 原因 |
| --- | --- | --- |
| 命名 | 独立名字，不含 `mastra` 商标；npm 用自己的 scope | 避免商标混淆 |
| LICENSE | 自己的 MIT；`NOTICE` 声明基于 Mastra（Apache-2.0）构建 | Apache-2.0 要求保留声明 |
| 规避 `ee/` | 不复制、不引用 Mastra 任何 `ee/` 目录 | 该部分适用专有许可 |
| 依赖审计 | 确认依赖树无 GPL / AGPL 传染性许可 | 避免许可污染 |

### B 档 · 决定项目有没有存在价值（应该）

| 项 | 做法 |
| --- | --- |
| 国产模型适配 | 六家统一适配，显式声明差异点 |
| 一键脚手架 | `create-nexagent`，交互式生成可运行项目 |
| 中文文档 | 快速开始 / 接入指南 / 排错，全部中文 |
| 示例集 | 替换官方英文示例，换成国内场景 |

### C 档 · 决定天花板（建议）

| 项 | 做法 |
| --- | --- |
| 企业 IM 接入 | 微信 / 企微已做，飞书 / 钉钉规划中 |
| 内容合规中间件 | 输入输出双向审核 + 审计钩子 |
| 可观测面板 | token 消耗、调用链路、失败重试 |
| 中文评测集 | 中文场景 Agent 评测用例，公开跑分 |

## 我们明确不做

- ❌ 不做另一个 Agent 内核
- ❌ 不做可视化编排平台（那是 Dify 的地盘）
- ❌ 不做个人微信 hook / 协议（违反平台规范、封号风险）
- ❌ 不做多租户 SaaS 后端

详见 [`VISION.md`](../VISION.md)。

## 一个关键工程决策

**不要把 Mastra 的源码复制进仓库。** 作为 npm 依赖引入，你的代码只写适配层。

这样做有三个好处：

1. **上游升级只需改 `package.json`** —— 不会被破坏性变更冲垮；
2. **仓库体积小、审查容易** —— 没有几万行别人的代码；
3. **法律边界清晰** —— 你发布的是「基于 Mastra 构建的项目」，
   而不是「Mastra 的分支」。

只有当某个包必须动内部逻辑时，才用 `patch-package`，或向上游提 PR。

## 那用户为什么不直接用 Mastra？

因为国内开发者的前三个卡点，Mastra 都不管：

1. 通义 / DeepSeek / GLM 怎么接？（它默认面向 OpenAI 系）
2. 怎么接到微信 / 飞书？（它不提供 IM 通道）
3. 内容审核怎么办？（框架层通常不管合规）

**这三件事，就是 NexAgent 的全部存在理由。**
